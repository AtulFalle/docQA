# M0: Foundations

Goal: a repository, local infrastructure, data model, evaluation seed, observability and CI/CD that every later milestone builds on. No user-facing features.

Each item lists the files that deliver it. A box is ticked when the listed files are on the branch and their checks pass in CI.

## Checklist

- [x] **Repo layout**: uv workspace with four Python packages (py-core, ai-api, ingestion-worker, eval); the Angular/NestJS apps are added per ADR 0005, each with its own `pyproject.toml`, src layout and `py.typed`.
  - `pyproject.toml`, `libs/py-core/`, `services/ai-api/`, `services/ingestion-worker/`, `eval/`
  - `.python-version`, `.editorconfig`, `.gitattributes`, `.gitignore`
- [x] **Local infrastructure**: Postgres, Redis, RustFS (with the `docqa-raw` bucket), Qdrant, Temporal and its UI, Langfuse, Grafana LGTM. Optional containerised app services behind the `app` profile.
  - `infra/docker/docker-compose.yml`
  - `infra/docker/postgres-init/01-create-databases.sql`
  - `.env.example`
  - `Makefile`, `README.md`
- [x] **Core data model**: tenants, users, groups, memberships, documents, ACLs, versions, chunks, jobs and audit log, with typed SQLAlchemy models.
  - `libs/py-core/src/docqa_core/db/models.py`, `base.py`, `session.py`
- [x] **Migration**: initial schema (now owned by Prisma in `apps/backend/prisma`, ADR 0005) with constraint names from the naming convention, and row-level security on every tenant-scoped table.
  - `apps/backend/prisma/migrations/` (the former Alembic migration was removed)
  - `libs/py-core/tests/test_core_schema_contract.py` checks the Python mirror against the migrated DB in CI.
- [x] **RLS leak test**: an integration test shows that a session with tenant A's context cannot read or write tenant B's rows.
  - `libs/py-core/tests/` (integration, marked `integration`)
- [ ] **Golden eval set v0**: 100 to 200 real questions with gold evidence, drawn from the real corpus.
  - Delivered so far: schema (`eval/src/docqa_eval/schema.py`), loader and validation (`dataset.py`), metrics (`metrics.py`), CLI (`cli.py`), synthetic seed (`eval/datasets/golden_v0.jsonl`), sample corpus (`eval/corpus/sample/`, `manifest.json`).
  - Pending: real questions once the real corpus is available. Owner to be assigned.
- [x] **Tracing and structured logging**: JSON logs with trace and span IDs, OpenTelemetry setup, request IDs on every API call.
  - `libs/py-core/src/docqa_core/logging.py`, `telemetry.py`, `config.py`
  - `services/ai-api/src/docqa_ai_api/middleware.py`, `services/ai-api/src/docqa_ai_api/main.py`
  - `otel-lgtm` in the compose file
- [x] **Decisions locked**: deployment target, LLM and embedding provider, data residency.
  - `docs/adr/0003-llm-and-embedding-provider.md`: Accepted, all models self-hosted.
  - `docs/adr/0004-data-residency.md`: Accepted, self-hosted processing and one region per deployment. Region and retention values are confirmed before real customer data is ingested.
  - `docs/adr/0002-deployment-target.md`: still Proposed (recommends portable Kubernetes). **Moved to M2**, as the exit criteria allow, because it is only needed for the first deployed environment. Decide by the start of M2.
- [x] **CI/CD**: lint, typecheck, tests with coverage, Prisma migrations (backend job), schema contract test, eval dataset validation, Docker build, and image publishing to GHCR on `main` and tags.
  - `.github/workflows/ci.yml`, `.github/workflows/cd.yml`
  - `.github/dependabot.yml`, `.github/pull_request_template.md`
  - `.pre-commit-config.yaml`
  - The `deploy` job is a placeholder until ADR 0002 is accepted.

## Exit criteria

- `make up` and `docker compose ... up -d` start every infra service with healthy dependencies.
- `make test` passes, including the RLS leak test.
- CI is green on `main`.
- All ADRs are accepted, or the remaining decisions are explicitly moved to M1 with a date.
- The golden set has at least 100 real questions, or the gap is accepted and recorded here.
